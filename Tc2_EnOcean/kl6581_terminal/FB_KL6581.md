## 1. 功能简述

**KL6581 EnOcean 主端子**（KL6581 EnOcean Master Terminal）的配置 + 通信驱动 FB。KL6581 是 K-bus 上一片**主端子**，下挂多达 8 个 KL6583 EnOcean 收发器（即"远端天线"形态——主端子在控制柜里，KL6583 通过专用线引到现场），可同时收发 EnOcean 电报。本 FB 负责：① 上电时配置 KL6581（K-bus 握手、设主从、激活总线），② 之后每个 PLC 周期驱动数据交换并维护内部状态结构 `STR_KL6581`，③ 把状态结构通过 `str_KL6581` 输出给下游所有 `FB_Rec_*` / `FB_Send_*` / `FB_EnOcean_Search` 块共享。

**整个 KL6581 体系只需一个本 FB 实例**，但工程里允许有最多 **64 个 KL6581 端子**（通过 `nIdx` 区分）。所有 send / receive 块必须**与本 FB 在同一 PLC task 中调用**。

## 2. 接口定义

### VAR_INPUT

```iecst
VAR_INPUT
    bInit : BOOL;
    nIdx  : USINT := 1;
END_VAR
```

| 名称 | 类型 | 默认值 | 说明（中文） |
|---|---|---|---|
| `bInit` | `BOOL` | — | 电平触发：TRUE 时启动 FB（执行 KL6301 配置流程，之后激活数据交换）。FALSE 时停用 |
| `nIdx` | `USINT` | `1` | KL6581 实例索引；项目里有多个 KL6581 端子时必须填唯一值（1..64）。`> 64` 报 `KL6581_idx_number_not_OK` 错 |

### VAR_OUTPUT

```iecst
VAR_OUTPUT
    bReady     : BOOL;
    bBusy      : BOOL;
    bError     : BOOL;
    iErrorID   : E_KL6581_Err;
    str_KL6581 : STR_KL6581;
END_VAR
```

| 名称 | 类型 | 说明（中文） |
|---|---|---|
| `bReady` | `BOOL` | 端子配置完成、可收发数据时为 TRUE。所有 `FB_Rec_*` / `FB_Send_*` 应在 `bReady = TRUE` 后才认为输出有效 |
| `bBusy` | `BOOL` | FB 处于忙状态（初始化中或发送中），此时不要再触发新发送 |
| `bError` | `BOOL` | 错误标志，与 `iErrorID` 配合使用 |
| `iErrorID` | `E_KL6581_Err` | 错误枚举（见 §4） |
| `str_KL6581` | `STR_KL6581` | **共享状态结构**：所有 send / receive / search / teach-in 块的 `str_KL6581` 入口都连到这里。结构内含 transmitter ID、ORG、4 字节数据、错误号、idx 等共享字段 |

### VAR_IN_OUT

```iecst
VAR_IN_OUT
    stKL6581_in  : KL6581_Input;
    stKL6581_out : KL6581_Output;
END_VAR
```

| 名称 | 类型 | 说明（中文） |
|---|---|---|
| `stKL6581_in` | `KL6581_Input` | 在 System Manager 链到 KL6581 端子的**输入字节区**（nStatus + CNODE + ORG + DB0..DB3 + ID0..ID3 + STATUS，共 12 字节） |
| `stKL6581_out` | `KL6581_Output` | 在 System Manager 链到 KL6581 端子的**输出字节区**（nControl + CNODE + ORG + DB0..DB3 + ID0..ID3 + STATUS，共 12 字节） |

## 3. 行为说明

**触发**：电平触发。`bInit = TRUE` 后本 FB 进入配置阶段；配置完成后 `bReady = TRUE`、`bBusy = FALSE`、`bError = FALSE` 时即进入正常运行——每个 PLC 周期通过 `stKL6581_in / stKL6581_out` 与端子交换数据，并把"最新收到的一帧 EnOcean 电报"信息暂存到 `str_KL6581`。

**严格调用约束**（PDF §4.1.2.1 Restrictions）：
1. **每个实例每个 PLC 周期只能调用一次**（不能在多分支里都调用同一实例）。
2. **必须每个 PLC 周期调用**（不能放进条件分支里偶尔调用）。
3. **本 FB 与所有挂载的 send / receive 块必须在同一 PLC task**（cross-task 调用会让 `str_KL6581` 出现脏读）。
4. **每个 PLC 项目最多 64 个实例**。

**初始化阶段**：`bInit = FALSE → TRUE` 后内部状态机走 KL6581 → KL6583 链路初始化（探查下挂的 KL6583 收发器、设置 EnOcean 网络参数、激活总线）。期间 `bBusy = TRUE`、`bReady = FALSE`。配置失败（如端子线没接好）→ `bError = TRUE`、`iErrorID = KL6581_NoComWithKL6581 (16#11)` 或 `KL6581_WrongTerminal (16#A)`。

**`str_KL6581` 的"传染"**：本 FB 把当前周期收到的最新电报（含 transmitter ID、ORG 类型、4 字节数据等）填进 `str_KL6581`。所有下游 `FB_Rec_*` 都从这里读，所以 send 与 receive 之间共享同一 cycle 数据。FB_Send_* 在发送时也把 PLC 端要发出的数据写入 `str_KL6581` 中的 `ptData`、`iErrorId` 等字段。

**多 KL6581 端子工程**：每片 KL6581 各开一个本 FB 实例，分别填 `nIdx := 1, 2, ...`；下游 send / receive 块通过自己 `str_KL6581` 输入接到对应实例的 `str_KL6581` 输出来路由。

**典型陷阱**：
- 把本 FB 放到 IF 分支里，导致部分周期不调用 → 端子超时 `KL6581_WatchdogError (16#10)`。
- send / receive 块放在不同 task → 数据错位、断续。
- 多个 KL6581 实例都用默认 `nIdx := 1` → `KL6581_idx_number_not_OK` 报错或不报错但数据串流。
- 接进 K-bus 但漏链 `stKL6581_in / stKL6581_out` → `KL6581_NoComWithKL6581 (16#11)`。

## 4. 错误码 / 返回值

`iErrorID : E_KL6581_Err` 枚举值（PDF §4.1.2.6）：

| `iErrorID` | 名称 | 含义 | 处理建议 |
|---|---|---|---|
| `16#0` | `NO_ERROR` | 无错 | — |
| `16#A` | `KL6581_WrongTerminal` | 错误的端子（链到的不是 KL6581） | 检查 System Manager 中实际链的端子型号 |
| `16#10` | `KL6581_WatchdogError` | 初始化超时 | 检查 K-bus 连接、KL6581 上电；FB 是否每周期调用 |
| `16#11` | `KL6581_NoComWithKL6581` | 与端子无通信 | 变量是否链到 System Manager？端子插好了？Clean all + rebuild all + Reload IO？ |
| `16#12` | `KL6581_idx_number_not_OK` | `nIdx > 64` | 修正 nIdx 到 1..64 |
| `16#13` | `KL6581_Switch_to_Stopp` | 端子停止与 KL6583 交换数据 | 检查 KL6583 供电、线缆 |
| `16#14` | `KL6581_not_ready` | 内部消息给下游 | 等 `bReady = TRUE`，无须特别处理 |
| `16#15` | `KL6581_No_KL6853_Found` | 没有 KL6583 接到主端子 | 检查 KL6583 物理连接 |
| `16#16` | `KL6581_TransmissionError` | 数据发不出去 | 检查 KL6583 地址（`by_Node` 是否在 1..8 范围）、KL6583 是否准备好 |

注：枚举 `KL6581_No_KL6853_Found` 是 PDF 原文拼写（应为 KL6583），本仓库照搬。

## 5. 使用注意 / 常见坑

- **每个 PLC 周期必须调用且只调一次**：CFC 自动可以用 boolean enable，但 ST 编程时不要放 `IF bInit THEN fbKL6581(...) END_IF`，而是 `fbKL6581(bInit := bInit, ...)` 永远调用、由 bInit 控制是否进入工作态。
- **task 一致性**：所有 `FB_Rec_*` / `FB_Send_*` / `FB_EnOcean_Search` / `FB_Rec_Teach_In*` 必须和 FB_KL6581 在同一 task。把 PLC 任务周期建议设短（PDF 推荐"give the task a lower interval time"——典型 10-20 ms）。
- **多 KL6581 实例必须各自 `nIdx` 唯一**：1..64。错配后 `KL6581_idx_number_not_OK` 直接报。
- **不要在 Init 阶段触发 send**：`bReady = TRUE` 之前任何发送都会失败。`FB_Send_*` 的应用层应判 `fbKL6581.bReady = TRUE` 再触发。
- **`str_KL6581` 共享**：所有下游 send / receive 都接同一 `str_KL6581` 实例。两个 KL6581 工程时**绝对**不要混接到错的实例。
- **不要把 FB_KL6581 与 FB_EnOceanReceive 混用**：这两套对应不同端子（KL6581 vs KL6021-0023），API 完全不通用。
- **多 KL6583 节点**（每片主端子最多挂 8 个）：发送时用 `by_Node` 指定（1..8），接收时也用 `byNode` 过滤；`by_Node := 0` 表示"接收所有 KL6583"。

## 6. 最小例程

> 配套可导入文件：[`examples/P_Demo_FB_KL6581.TcPOU`](../examples/P_Demo_FB_KL6581.TcPOU)
>
> 导入步骤：右键 PLC 项目下 POUs 文件夹 → Add → Existing Item → 选该文件 → OK

```iecst
PROGRAM P_Demo_FB_KL6581
VAR
    fbKL6581       : FB_KL6581;
    stKL6581Input  AT %I* : KL6581_Input;
    stKL6581Output AT %Q* : KL6581_Output;
    bInitKL        : BOOL := TRUE;
    bKLReady       : BOOL;
    bKLError       : BOOL;
    iKLErrId       : E_KL6581_Err;
END_VAR
fbKL6581(
    bInit        := bInitKL,
    nIdx         := 1,
    stKL6581_in  := stKL6581Input,
    stKL6581_out := stKL6581Output,
    bReady       => bKLReady,
    bError       => bKLError,
    iErrorID     => iKLErrId
);
```

## 7. 业务场景与实际价值

- **场景**：项目里要接 EnOcean 无线设备，且 KL6021-0023 不够用——KL6021-0023 是"端子自带天线"，覆盖距离短（典型 30 m）。KL6581 + 远端 KL6583 的好处是天线可以拉到楼上 / 楼下 / 隔壁房间，最多 8 个 KL6583 节点共一片主端子，覆盖整栋办公楼。本 FB 是 KL6581 体系的"通信主入口"。
- **价值**：把 KL6581 端子配置 + K-bus 数据交换 + 8 节点 KL6583 调度 + 错误状态机封装为单 FB；应用层只看 `bReady` 与 `iErrorID`。下游 send / receive / search 块共享 `str_KL6581`。
- **替代方案对比**：
  - 用 KL6021-0023：覆盖距离短，单天线；适合小空间
  - 用 EL6233 (EtherCAT EnOcean 模块)：现代选项，需 EtherCAT 主站
  - **本 FB**：覆盖大、可扩展、与 KL 端子系统兼容；是楼宇 BMS 经典选型
