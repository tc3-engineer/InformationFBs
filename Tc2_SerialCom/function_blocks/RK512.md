## 1. 功能简述

实现 RK512 协议的功能块。RK512 是建立在 3964R 之上的高层协议，支持按"数据块号"读写远端的数据块。它有被动和主动两种工作模式：被动模式等待并响应对端的数据报文（对端可向本机写数据块或从本机取数据块，被动模式前须用 `DBconfig()` 方法登记可被访问的数据块）；主动模式由 `Send` 向对端发数据块、或由 `Fetch` 从对端取数据块。一个实例只服务一个串口。

## 2. 接口定义

### VAR_INPUT

```iecst
VAR_INPUT
  Send         : BOOL;  (* SEND command *)
  Fetch        : BOOL;  (* FETCH command *)
  DbAdr        : POINTER TO BYTE; (* ADR(DB), SEND=source, FETCH=target *)
  DbSize       : UINT;  (* SIZEOF(DB), size in byte for Send or Fetch *)
  RemoteDbNr   : BYTE;  (* SEND=target, FETCH=source *)
  NrOfBytes    : UINT;  (* number of bytes to send or fetch *)
  ByteOffset   : UINT;  (* byte offset in remote DB *)
  HighPriority : BOOL;  (* 3964R priority *)
  SwapWords    : BOOL;  (* swaps every two bytes in the data stream before/after transmission *)
  TREA         : TIME;  (* Timeout for answer *)
END_VAR
```

| 名称 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `Send` | `BOOL` | — | 上升沿把 `DbAdr` 处的数据发给对端、存入其编号为 `RemoteDbNr` 的数据块。Send 与 Fetch 不能同时执行 |
| `Fetch` | `BOOL` | — | 上升沿从对端编号 `RemoteDbNr` 的数据块取数据、存入 `DbAdr` 处变量。Send 与 Fetch 不能同时执行 |
| `DbAdr` | `POINTER TO BYTE` | — | PLC 变量地址，用 `ADR()` 取。可为任意类型（如 `ARRAY OF WORD` 或 `STRUCT`）；Send 时从此变量发出，Fetch 时存入此变量 |
| `DbSize` | `UINT` | — | `DbAdr` 处 PLC 变量的字节大小，用 `SIZEOF()` 取 |
| `RemoteDbNr` | `BYTE` | — | 对端数据块号，数据发往 / 取自该数据块 |
| `NrOfBytes` | `UINT` | — | 要传输的字节数，可小于等于 `DbSize` |
| `ByteOffset` | `UINT` | — | 在对端数据块中读 / 写的起始字节偏移 |
| `HighPriority` | `BOOL` | — | 3964R 优先级。两端应不同；同时发送冲突时低优先级一方转入接收，让高优先级一方重发 |
| `SwapWords` | `BOOL` | — | 数据块通常按字组织。视字节在内存中的存放方式，可能需要交换字内字节；为 `TRUE` 时所有数据报文中每个字的两字节互换 |
| `TREA` | `TIME` | — | 每个报文都要等对端应答报文，用 `TREA` 监控应答时间，`TREA` 约 15 秒 |

### VAR_IN_OUT

```iecst
VAR_IN_OUT
  TxBuffer         : ComBuffer;
  RxBuffer         : ComBuffer;
END_VAR
```

| 名称 | 类型 | 说明 |
|---|---|---|
| `TxBuffer` | `ComBuffer` | RK512 使用的发送缓冲区，用户不修改 |
| `RxBuffer` | `ComBuffer` | RK512 使用的接收缓冲区，用户不修改 |

### VAR_OUTPUT

```iecst
VAR_OUTPUT
  Busy             : BOOL;   (* FB is busy *)
   (* send or fetch (active) mode *)
  BusySendFetch    : BOOL;   (* FB is with SendFetchCommand busy *)
  SendFetchSuccess : BOOL;   (* Send or Fetch successfully finished *)
  Error            : BOOL;   (* RK512 error *)
  ErrorId          : RK512_Error_t;    (* RK512 error id *)
   (* receive (passive) mode only *)
  BusyReceive      : BOOL;   (* FB is busy with remote request *)
  ReceiveSuccess   : BOOL;   (* DB has been received from the remote PLC *)
  ReceivedDbNr     : BYTE;   (* Number of the DB that has been received *)
  ErrorRx          : BOOL;   (* RK512 error. For receive mode only *)
  ErrorIdRx        : RK512_Error_t;    (* RK512 error id. For receive mode only *)
  Aux              : RK512_Auxiliary_t;  (* Additional errors for debugging *)
END_VAR
```

| 名称 | 类型 | 说明 |
|---|---|---|
| `Busy` | `BOOL` | 功能块进入主动或被动模式（离开空闲态）即为 `TRUE`；为 `TRUE` 时不能接受新命令 |
| `BusySendFetch` | `BOOL` | `Send` / `Fetch` 上升沿使其进入主动模式时为 `TRUE`；变 `FALSE` 后传输完成，置位 `SendFetchSuccess` 或 `Error` |
| `SendFetchSuccess` | `BOOL` | `Send` / `Fetch` 触发的数据传输成功完成 |
| `Error` | `BOOL` | `Send` / `Fetch` 触发的传输中出错为 `TRUE` |
| `ErrorId` | `RK512_Error_t` | 出错时给出错误号（见 §4） |
| `BusyReceive` | `BOOL` | 功能块处于被动接收模式（自动从空闲态进入）。下降沿时置位 `ReceiveSuccess` 或 `ErrorRx` |
| `ReceiveSuccess` | `BOOL` | 成功从对端被动接收一个数据块后置位（仅被动模式相关；主动 Fetch 不置位） |
| `ReceivedDbNr` | `BYTE` | `ReceiveSuccess` 为 `TRUE` 时给出收到的数据块号 |
| `ErrorRx` | `BOOL` | 被动模式接收数据时出错为 `TRUE` |
| `ErrorIdRx` | `RK512_Error_t` | 被动模式出错时给出错误号（见 §4） |
| `Aux` | `RK512_Auxiliary_t` | 含额外错误信息的诊断数据结构 |

### DBconfig() 方法

`RK512` 功能块带一个 `DBconfig()` 方法，用于被动模式下登记可被对端访问的"编号数据块"。被动模式下对端用数据块号寻址，而 IEC-1131 / TwinCAT 没有"编号数据块"概念（数据块在 TwinCAT 里就是数组 / 结构体变量）。因此初始化阶段须为每个允许被访问的数据块调一次 `DBconfig()`。主动模式（Send / Fetch）不需要此配置。参数：`DbAdr`（PLC 变量地址，`ADR()`）、`DbSize`（字节大小，`SIZEOF()`）、`RemoteDbNr`（对端引用的数据块号）、`TxBuffer` / `RxBuffer`（`ComBuffer`，配置本身不用但须作为 IN_OUT 参数传入）。

## 3. 行为说明

RK512 在被动与主动两种模式间自动切换：

**被动模式（接收）**：空闲态（`Busy = FALSE`）下一旦收到对端报文，功能块自动进入被动模式，`BusyReceive = TRUE`；`BusyReceive` 下降沿时根据结果置位 `ReceiveSuccess`（成功收到数据块，`ReceivedDbNr` 给出块号）或 `ErrorRx`（接收出错，`ErrorIdRx` 给错误号）。被动模式前必须用 `DBconfig()` 登记好对端可访问的数据块，否则对端访问未登记的数据块会被拒绝（报 `RK512ERR_DBNOTAVAILIBLE`）。

**主动模式（发送 / 取数）**：`Send` 上升沿把本地 `DbAdr` 的数据发给对端 `RemoteDbNr` 数据块（从 `ByteOffset` 起写 `NrOfBytes` 字节）；`Fetch` 上升沿从对端 `RemoteDbNr` 取数据存入本地 `DbAdr`。两者不能同时执行。进入主动模式后 `BusySendFetch = TRUE`，完成后根据结果置位 `SendFetchSuccess` 或 `Error`（`ErrorId` 给错误号）。每个报文都要等对端应答，超时由 `TREA`（约 15 秒）监控。

**混合模式**：两种模式可混用，功能块会尝试同步报文流，但混用会引入延迟，应尽量避免。一个 RK512 实例只能服务一个串口，不能多个实例共用同一串口。

**优先级与字节序**：`HighPriority` 对应底层 3964R 的冲突仲裁，两端须一高一低。`SwapWords = TRUE` 时交换每个字内的两字节，用于两端字节序不一致的场合。

底层 3964R 协议层和硬件收发仍由对应的协议 / 后台功能块承担——RK512 通过 `TxBuffer` / `RxBuffer` 与之衔接，这两个缓冲用户不直接读写。

## 4. 错误码 / 返回值

主动模式错误在 `ErrorId`、被动模式错误在 `ErrorIdRx`，均为 `RK512_Error_t` 枚举（PDF 第 7.5 节，节选）：

| Code (dec) | Code (hex) | 错误常量 | 含义 |
|---|---|---|---|
| 4 | `16#04` | `RK512ERR_P3964ERR_ZVZ` | 字符延迟超时（ZVZ = 220 ms） |
| 5 | `16#05` | `RK512ERR_P3964ERR_QVZ` | 确认延迟超时（QVZ = 2 s），见 `ErrorState` 区分握手阶段 |
| 6 | `16#06` | `RK512ERR_P3964ERR_WVZ` | 重复延迟超时（WVZ = 4 s） |
| 7 | `16#07` | `RK512ERR_P3964ERR_WRONGBCC` | 接收校验和错误 |
| 9 | `16#09` | `RK512ERR_P3964ERR_COMERRTX` | 发送时接口错误 |
| 10 | `16#0A` | `RK512ERR_P3964ERR_COMERRRX` | 接收时接口错误 |
| 11 | `16#0B` | `RK512ERR_P3964ERR_NOTXDATA` | 待发字节数为 0 |
| 120 | `16#78` | `RK512ERR_P3964ERR_NAK` | 对端用 NAK 拒收报文 |
| 12 | `16#0C` | `RK512ERR_INVALIDDATATYPE` | 数据类型无效：仅支持标识符为 'D' 的数据块 |
| 16 | `16#10` | `RK512ERR_ERRORPROTOCOLHEADER` | 协议头错误：报文头不符合 RK512 规范 |
| 20 | `16#14` | `RK512ERR_DBNOTAVAILIBLE` | 数据块不可用：访问了未用 `DBconfig` 登记的数据块 |
| 22 | `16#16` | `RK512ERR_INVALIDCOMMAND` | 命令无效：收到非法命令 ID（非 SEND / FETCH） |
| 52 | `16#34` | `RK512ERR_INVALIDSIZE` | `DbSize` / `NrOfBytes` 无效，或收到的报文过长 |
| 53 | `16#35` | `RK512ERR_INVALIDDBADR` | 数据块地址 `DbAdr` 无效 |
| 54 | `16#36` | `RK512ERR_SYNCERROR` | 同步错误：两端同时开始发送时可能发生 |
| 257 | `16#101` | `RK512ERR_TIMEOUT` | RK512 报文级超时：`TREA` 内未收到期望的应答报文 |
| 258 | `16#102` | `RK512ERR_ERRORREMOTEREATEL` | 对端应答报文含错误信息，错误号见 `Aux` |
| 259 | `16#103` | `RK512ERR_INVALIDSIZEREMOTEREATEL` | 对端应答报文长度不对 |
| 260 | `16#104` | `RK512ERR_TIMEOUTREAPEATSENDFETCH` | 发送超时：多次尝试仍未能发出 Send / Fetch 报文 |
| 261 | `16#105` | `RK512ERR_3964ERROR` | 3964R 协议层错误（可预见的错误用专门错误号，不归这条） |
| 262 | `16#106` | `RK512ERR_3964NOTBUSYNOTREADY` | 报文传输未成功完成即中止 |

转事件日志可用 `RK512Error_TO_TcEventEntry`（配合 Tc3_EventLogger）。

## 5. 使用注意 / 常见坑

- **被动模式必须先 `DBconfig`**：对端要读写的每个数据块都得在初始化时用 `DBconfig()` 登记好（给 `RemoteDbNr` / `DbAdr` / `DbSize`），否则对端访问会被拒（`RK512ERR_DBNOTAVAILIBLE`）。
- **Send 与 Fetch 互斥**：不能同时触发。
- **一实例一串口**：一个 RK512 实例只能管一个串口，不能多实例共用。
- **`TREA` 要够大**：应答超时约 15 秒，太小会误报 `RK512ERR_TIMEOUT`。
- **字节序**：两端字节序不一致时用 `SwapWords := TRUE`。
- **被动 / 主动错误分开看**：被动接收错误在 `ErrorIdRx`，主动 Send/Fetch 错误在 `ErrorId`，诊断细节在 `Aux`。
- **避免混合模式**：主被动混用会引入延迟，能避免则避免。

## 6. 最小例程

> 配套可导入文件：[`examples/P_Demo_RK512.TcPOU`](../examples/P_Demo_RK512.TcPOU)

```iecst
// 场景：主动模式 SEND——把本地数据块发给对端 DB5。
PROGRAM P_Demo_RK512
VAR
    fbRK512  : RK512;
    DB5      : ARRAY[1..64] OF WORD;
    bufTx    : ComBuffer;
    bufRx    : ComBuffer;
    bSend    : BOOL;
    bSuccess : BOOL;
END_VAR

fbRK512(
    Send         := bSend,
    Fetch        := FALSE,
    DbAdr        := ADR(DB5),
    DbSize       := SIZEOF(DB5),
    RemoteDbNr   := 5,
    NrOfBytes    := SIZEOF(DB5),
    ByteOffset   := 0,
    HighPriority := TRUE,
    SwapWords    := FALSE,
    TREA         := T#15S,
    TxBuffer     := bufTx,
    RxBuffer     := bufRx,
    SendFetchSuccess => bSuccess
);
```

## 7. 业务场景与实际价值

- **场景**：与西门子 S5 / S7 等支持 RK512 的设备做数据块级别的串行数据交换，常见于老产线改造、与西门子侧串口接口对接需要按 DB 号读写的场合。
- **价值**：把"按数据块号读写远端"的协议细节（报文格式、3964R 握手、应答超时、错误诊断）全部封装；应用层只给 PLC 变量地址 + 数据块号即可 Send / Fetch，被动侧用 `DBconfig` 登记后自动响应。
- **替代方案对比**：只需带握手的可靠字节流、无需数据块编址用 `3964R`；无可靠性要求的简单收发用 `Send*` / `Receive*`；RK512 用于需要数据块语义的场景。
