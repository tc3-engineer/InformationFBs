## 1. 功能简述

实现 3964R 串行通信协议的功能块（库内 FB 类型名为 `P3964R`）。3964R 是西门子定义的点对点串行协议，带起始 / 结束控制字符、超时监控和校验和（BCC），保证数据可靠传输。底层硬件收发仍由 `SerialLineControl` 完成，本功能块只处理 3964R 协议层；通过 `TxBuffer` / `RxBuffer`（`ComBuffer`）与之衔接。它可工作在发送或接收模式，由 `TXstart` / `RXstart` 边沿切换。

## 2. 接口定义

### VAR_INPUT

```iecst
VAR_INPUT
  TXstart  : BOOL;    (* start signal, edge-triggered *)
  RXstart  : BOOL;    (* start signal, edge-triggered *)
  Priority : BOOL;    (* 3964 priority, TRUE=high, FALSE=low *)
  TXcount  : INT;     (* number of data bytes in TxData *)
END_VAR
```

| 名称 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `TXstart` | `BOOL` | — | 边沿触发的发送启动信号。新一次发送前须先以 `TXstart = FALSE` 调用，再置 `TRUE` 启动发送 |
| `RXstart` | `BOOL` | — | 边沿触发的接收启动信号，置 `TRUE` 进入接收模式 |
| `Priority` | `BOOL` | — | 3964R 优先级，`TRUE`=高、`FALSE`=低。双方同时发送会冲突，低优先级一方转入接收，高优先级一方继续发；优先级低时即使有数据要发 `RXready` 也可能为 `TRUE`，须评估 `RXdata`。两端优先级须事先约定 |
| `TXcount` | `INT` | — | 待发数据字节数，传给 `TXcount` |

### VAR_IN_OUT

```iecst
VAR_IN_OUT
  TXdata          : P3964buffer;  (* application data (to send)*)
  RXdata          : P3964buffer;  (* application data (received)*)
  TxBuffer        : ComBuffer;    (* buffer between protocol software and terminal *)
  RxBuffer        : ComBuffer;    (* buffer between protocol software and terminal *)
END_VAR
```

| 名称 | 类型 | 说明 |
|---|---|---|
| `TXdata` | `P3964buffer` | 应用层发送数据缓冲区，由 PLC 写入待发数据 |
| `RXdata` | `P3964buffer` | 应用层接收数据缓冲区，收到的 `RXcount` 个字节存于此 |
| `TxBuffer` | `ComBuffer` | 协议软件与端子之间的发送缓冲（接 `SerialLineControl`） |
| `RxBuffer` | `ComBuffer` | 协议软件与端子之间的接收缓冲（接 `SerialLineControl`） |

### VAR_OUTPUT

```iecst
VAR_OUTPUT
  Busy       : BOOL;           (* block is active *)
  TXbusy     : BOOL;           (* send state *)
  TXready    : BOOL;           (* send completed, data were transferred *)
  RXbusy     : BOOL;           (* receive state *)
  RXready    : BOOL;           (* receive completed, data were transferred *)
  RXcount    : INT;            (* number of data bytes in RxData *)
  Error      : BOOL;           (* error *)
  ErrorID    : P3964R_Error_t; (* error id *)
  ErrorState : STRING(80);     (* internal error state *)
END_VAR
```

| 名称 | 类型 | 说明 |
|---|---|---|
| `Busy` | `BOOL` | 功能块活动中；传输结束后回到基态（`Busy = FALSE`） |
| `TXbusy` | `BOOL` | 发送进行中为 `TRUE` |
| `TXready` | `BOOL` | 数据成功发送完毕后为 `TRUE` |
| `RXbusy` | `BOOL` | 接收进行中为 `TRUE` |
| `RXready` | `BOOL` | 完整接收一组数据后为 `TRUE` |
| `RXcount` | `INT` | `RXdata` 中收到的数据字节数 |
| `Error` | `BOOL` | 出错时为 `TRUE`，功能块回到初始态（`Busy = FALSE`） |
| `ErrorID` | `P3964R_Error_t` | 错误码（见 §4） |
| `ErrorState` | `STRING(80)` | 内部协议结构已知时，提供出错时所处的状态信息 |

## 3. 行为说明

3964R 是带握手的可靠点对点协议，功能块工作在发送或接收两种模式：

**发送**：PLC 把待发数据写入 `TXdata`，把字节数写入 `TXcount`，再给 `TXstart` 上升沿启动发送；发送期间 `TXbusy = TRUE`，数据成功传完后 `TXready = TRUE`。`TXstart` 是边沿触发，下次发送前必须先以 `TXstart = FALSE` 调一次。

**接收**：给 `RXstart` 上升沿进入接收模式；收到完整一组数据后 `RXready = TRUE`，`RXcount` 给出字节数，数据在 `RXdata`，接收期间 `RXbusy = TRUE`。

**中断接收发送**：功能块处于接收模式但尚未收到对端起始字符时，一个 `TXstart` 上升沿可中断接收、转去发送；传输后功能块回到初始态（`Busy = FALSE`），需新的 `RXstart` 边沿才再次进入接收。

**优先级与冲突**：3964R 中任一端都可随时发送，双方同时发送会冲突——低优先级一方转入接收、高优先级一方重发。因此当本端优先级低时，即使有数据待发，`RXready` 也可能变 `TRUE`（先收下了对端数据），此时 `RXdata` 需要评估。两端优先级必须事先约定为一高一低。

**出错**：`Error = TRUE` 时功能块回到初始态，`ErrorID`（`P3964R_Error_t`）给错误码，`ErrorState` 给出错时所处的协议状态（如 `Wait_DLE_TXstart` / `Wait_DLE_TXend`），便于定位是握手哪一步出的问题。

## 4. 错误码 / 返回值

`Error`（`BOOL`）置位时，`ErrorID` 为 `P3964R_Error_t` 枚举（PDF 第 7.4 节）：

| Code (dec) | Code (hex) | 错误常量 | 含义 |
|---|---|---|---|
| 4 | `16#04` | `P3964ERR_ZVZ` | 字符延迟时间超时（ZVZ = 220 ms）：两个连续字符之间间隔过长 |
| 5 | `16#05` | `P3964ERR_QVZ` | 确认延迟时间超时（QVZ = 2 s）：传输起始（`Wait_DLE_TXstart`）或用户数据发完后（`Wait_DLE_TXend`）未在规定时间收到确认字符（DLE）；可能是物理连接故障、接口参数错或数据丢失 / 损坏 / 字节交换 |
| 6 | `16#06` | `P3964ERR_WVZ` | 重复延迟时间超时（WVZ = 4 s）：出错时会重发，对端未重发则报此错 |
| 7 | `16#07` | `P3964ERR_WRONGBCC` | 接收时校验和（BCC）错误 |
| 9 | `16#09` | `P3964ERR_COMERRTX` | 发送时接口错误 |
| 10 | `16#0A` | `P3964ERR_COMERRRX` | 接收时接口错误 |
| 11 | `16#0B` | `P3964ERR_NOTXDATA` | 参数错误：待发字节数 `TXcount` 为 0 |
| 20 | `16#14` | `P3964ERR_NAK` | 对端用否定确认（NAK）拒收报文（可能发生在 `Wait_DLE_TXstart` 或 `Wait_DLE_TXend` 状态，后者常因对端校验和错） |

转事件日志可用 `P3964RError_TO_TcEventEntry`（配合 Tc3_EventLogger）。

## 5. 使用注意 / 常见坑

- **`TXstart` / `RXstart` 边沿触发**：每次启动前须先复位对应输入再给上升沿。
- **两端优先级一高一低**：必须事先约定，否则冲突无法正确解决。优先级低时 `RXready` 可能在你想发时变 `TRUE`，要先处理收到的数据。
- **底层要有 `SerialLineControl`**：本功能块只管协议层，硬件收发靠 `SerialLineControl` 搬运 `TxBuffer` / `RxBuffer`。
- **看 `ErrorState` 定位握手阶段**：超时 / NAK 错误时 `ErrorState`（如 `Wait_DLE_TXstart` / `Wait_DLE_TXend`）能指出卡在握手哪一步。
- **`TXcount` 不能为 0**：否则报 `P3964ERR_NOTXDATA`。

## 6. 最小例程

> 配套可导入文件：[`examples/P_Demo_3964R.TcPOU`](../examples/P_Demo_3964R.TcPOU)

```iecst
// 场景：用 3964R 协议与西门子设备点对点收发。
PROGRAM P_Demo_3964R
VAR
    fb3964R   : 3964R;
    txData    : P3964buffer;
    rxData    : P3964buffer;
    bufTx     : ComBuffer;
    bufRx     : ComBuffer;
    bTxStart  : BOOL;
    bRxStart  : BOOL := TRUE;        // 默认进接收态
    bTxReady  : BOOL;
    bRxReady  : BOOL;
END_VAR

fb3964R(
    TXstart  := bTxStart,
    RXstart  := bRxStart,
    Priority := TRUE,                // 本端高优先级
    TXcount  := 4,
    TXdata   := txData,
    RXdata   := rxData,
    TxBuffer := bufTx,
    RxBuffer := bufRx,
    TXready  => bTxReady,
    RXready  => bRxReady
);
```

## 7. 业务场景与实际价值

- **场景**：与使用 3964R 协议的西门子 PLC / 设备做可靠点对点串行通信（带握手、校验、重传），常见于改造老产线、对接西门子侧串口接口。
- **价值**：把 3964R 的控制字符握手、超时监控、BCC 校验、冲突仲裁、重传全部封装；应用层只需读写 `TXdata` / `RXdata` 并控制 `TXstart` / `RXstart`。
- **替代方案对比**：要带数据块编址的更高层协议用 `RK512`（建立在 3964R 之上）；无需可靠握手的简单收发直接用 `Send*` / `Receive*` 功能块。
